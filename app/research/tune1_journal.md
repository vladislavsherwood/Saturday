# tune1 — шлифовка покупок у дна (капитуляция, волна ликвидаций, отложенная после выноса)

Основа — combo2 (`app/found/combo2-best.json`, 59 правил; `combo2_sim.build({a1, as, cm2, b65:'list'})` воспроизводит их один в один):
отбор 17 — 2174%, экзамен 14 — 1436%, 50 случайных — 459%, 100 новых — 390% (91 / 176). Мои три правила — первые три покупки:
#0 капитуляция `fng < 10 → 25%`, #1 отложенная `dly20_100f → 50%`, #2 волна `oidd30 < −28 → 50%`.

**Инструменты.** `app/tune1_sim.js` — свои индикаторы на монете по `found/liq_extra.json` (как `liq_inject.js`/`ls_inject.js`):
`oiddW{W}` — OI BTC к максимуму за W дней; `dlyT{w}_{t}_{x}_{y}_{W}{m}` — отложенная с окном w, порогом выноса t, толпой сейчас > x,
мин. толпы за w дней < y, окном максимума OI W, режимом дней m (`f` — только первый день, `kN` — первые N дней подряд, `a` — все дни).
Проверка: при W=30 и параметрах по умолчанию совпадение с `oidd30` и `dly20_100f` на всех 323 тыс. днях — 0 расхождений.
`ev`/`cmp` — сводка по группам и сегментам, доход (сумма лог-медиан отбор+экзамен+50 случ.), строгая проверка всей выборки и
сегментов (крупные/альты/мемы) через `combo2_sim.strict`. `app/tune1_show.js` — краткая таблица развёрток.
Критерий принятия (заранее): строгая ✔ во всей выборке и в каждом сегменте, доход сегментов ≥ 0, и **плато** — соседние значения
(±1 шаг с обеих сторон) тоже ✔ и с доходом не ниже −0,01 к выбранному. 100 новых — только в финале.

где результат не меняется вовсе (27–37, 14–20, 0,80–0,90): там нечего точить; 20 и 0,9 — у правого края своих плато, но середина
даёт ровно то же (те же дни сигнала), смысла сдвигать нет. Пороги выноса −28 (оба правила) и страх < 10 — острые пики
(±0,5 п.п. OI = −0,02…−0,07 или ломка строгой). Доли гладкие и почти плоские (±10 п.п. = ±0,01…0,02 дохода), любая не-нулевая
правка задевает худшую монету/половину на сотые доли п.п. — строгая не пускает. Кандидаты с доходом на круг 2: волна −27,5…−26
(+0,11…+0,15, ломает SOL и мемы), отложенная «k2» (+0,077), толпа > 1,02–1,03 (+0,064). Принятых изменений нет.

Примечание (от координатора/imp8): упрощение `imp8_sim.simplifyC` убирает 4 мёртвых правила combo2 без изменения результата;
мои три правила (#0–#2) оно не трогает, поэтому развёртки идут на полной сборке combo2 (59 правил) — результаты те же.
Любой сдвиг **порога** принимается только при выигрыше «вперёд по времени» на всех Y (круг 2); доли — по плато, как обычно.

## Круг 2. «Вперёд по времени» для порогов (`app/tune1_r2.js`, scratchpad/tune1/r2.json)

**Гипотеза (заранее).** Пороги, которые на всей истории выглядят выгодными (волна −27…−26, толпа > 1,02, страх < 11–13, «первые 2–3 дня»),
при подборе только по данным до Y = 2021/2022/2023/2024 будут выбраны иначе и после Y проиграют или дадут ≈0; текущие −28 / 10 / 1,0 — нет.
Метод: окно [начало, Y) — подбор по сумме лог-медиан отбор+экзамен+50 случ. (старт с нуля в окне, монеты ≥ 365 дней, `imp8_sim.EW`),
проверка выбранного против combo2 на [Y, конец). Данные OI начинаются в 2020–21 г., поэтому «до 2021» сигналов OI нет (выбор = текущее).

| порог | выбор до 2021 / 2022 / 2023 / 2024 | после Y к combo2 | вывод |
|---|---|---|---|
| капитуляция fng < 10 | 14 / 13 / 10 / 10 | −0,222 / −0,016 / 0 / 0 | подбор по прошлому проигрывает — оставить 10 |
| волна oidd30 < −28 | −28 / −25,5 / −33 / −23,5 | 0 / −0,128 / 0 / −0,182 | выбор скачет от −33 до −23,5 и проигрывает — пик −28 случайный, но сдвиг хуже; оставить |
| отложенная: порог выноса −28 | −28 / −28 / −28 / −28 | 0 | на всех Y выбирается текущее — устойчиво |
| отложенная: толпа > 1,0 | 1,0 / 1,02 / 1,06 / 1,02 | 0 / 0 / 0 / 0 | после 2022 разница 0 (сигналы совпадают) — выигрыша вне выборки нет |
| отложенная: первые N дней | f / k3 / k3 / k2 | 0 / +0,001 / 0 / 0 | выигрыш вне выборки ≈0 |

Строки таблиц: волна −27,5 «после» +0,038 / +0,001 / 0 / 0 (на всех Y не хуже), но в подборе до 2022/2023 её не выбрать
(−0,014 / −0,002 в окне) — это значение видно только «задним числом» (весь выигрыш даёт 2024–2026), и строгая всей истории
ломается (SOL 454 → 434%). Отложенная k3 «до» +0,22…+0,35 в 2022–23, но «после» +0,001 — выигрыш живёт только внутри окна подбора.

**Вывод.** Подтверждена. Ни один сдвиг порога не даёт выигрыша вне выборки: для волны и капитуляции подбор по прошлому прямо
проигрывает (−0,13…−0,22), для отложенной — даёт 0. Пороги своей части оставляю: страх < 10, OI < −28 (оба правила), толпа > 1,0,
«только первый день». Изменений нет.

## Круг 3. Доли трёх покупок вместе (`app/tune1_r3.js`, scratchpad/tune1/r3.json)

**Гипотеза (заранее).** Поодиночке каждая доля задевает строгую (худшая монета/половина) на сотые доли п.п.; вместе сдвиги могут
компенсировать друг друга (капитуляция вверх + волна вниз), и найдётся точка со строгой ✔ и доходом > 0 на плато.
Сетка 2,5 п.п.: капитуляция 20–30%, отложенная 45–60%, волна 42,5–57,5% (245 точек); мелкий шаг 0,5 п.п. — вокруг лучших прошедших.

Результат: весь куб даёт доход от −0,031 до +0,027 — доли почти не важны (плато по доходу). Строгую с доходом > 0 не прошла
**ни одна** точка; без нарушений только combo2 (25/50/50) и сдвиги вниз (25/47,5/47,5 −0,001; 25/45/50 −0,005). Лучшая по доходу
30/60/42,5 (+0,027: альты +0,04, мемы +0,025) ломает 9 пунктов строгой: худшая монета отбора 18,40 → 18,38%, худшая монета и
худшая половина экзамена (мем) на −0,0x п.п. — бо́льшая трата резерва на капитуляции слегка вредит худшим монетам.
Ближе всех 25/50/47,5 (+0,0015, одно нарушение: худший альт экзамена 254,1 → 253,9%).

**Вывод.** Отвергнута. Текущие доли 25/50/50 стоят на ровном плато (±5 п.п. = ±0,01 дохода) и в его «строгой» точке: любой выигрыш
дохода покупается худшими монетами. Мелкий шаг не запускался (не было прошедших точек). Изменений нет.
