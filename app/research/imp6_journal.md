# Агент улучшения №6 (imp6): реальное исполнение

Основа — `app/found/combo-best.json` + `combo-best-margin.json` (`combo2-best.json` на старте не было).
Портфельная модель — `agent4d_margin.sim4` (решение по закрытию дня t−1 исполняется по закрытию дня t; «на день позже» — по закрытию t+1).
Свои инструменты: `app/imp6_common.py` (сдвиг исполнения по семействам правил), `app/imp6_sim.py` (sim5 = sim4 + размазывание сделок,
условия Hyperliquid: комиссии по монете, перп-монеты с фандингом, минимальный ордер, ликвидация по залогу USDC + PnL перпов;
при параметрах по умолчанию совпадает с sim4 до 1e-12, `app/imp6_chk.py`).
Цифры — медиана итога к вкладам 105 стартов, лучшая безопасная схема (R16 + A4 ×1,4 + шорт BTC 20%), пять портфелей P9 / B / M / P2+BTC / P3+BTC.

## Круг 2. Размазывание сигнальных сделок на 2–3 дня

итог перестанет зависеть от точного дня исполнения: среднее и худший из сдвигов −1 / в срок / +1 вырастут на всех пяти портфелях,
ценой небольшой потери «в срок». Критерий: среднее и минимум по сдвигам {−1, 0, +1} выше основы на всех пяти портфелях, 0 ликвидаций
в стрессе −20/−30% при **всех трёх** сдвигах (раньше проверяли только 0 и +1). Скрипты `app/imp6_r2.py` (sim5: WT — доли по дням, SPL — какие группы плеча),

4. Убирать плечо со второй половины нельзя: −20…−25% медианы.

## Круг 3. Стратегия в условиях Hyperliquid

**Гипотеза (заранее).** Комиссии HL ниже модельных (+1–2%), фандинг DOGE/PEPE и минимальный ордер стоят по 2–4% медианы P9,
а главное, что может сломаться, — ликвидационный профиль: на HL залог перпов — только USDC и PnL перпов, спот не считается
(hyperliquid_exec.md, раздел 3). Ожидаю, что схема «спот на v + лонг перпа на (L−1)·v» ломается после трат резерва на панике,
и что исправление — держать плечевую часть с отдельным залогом или всю позицию на перпах. Критерий исправления: 0 ликвидаций
по правилу HL (залог ≤ Σ поддерживающая маржа: BTC 1,25%, ETH 2%, SOL 2,5%, альты 5%, шорт BTC 1,25%) **и** по модельному правилу,
на пяти портфелях, при сдвигах −1/0/+1 и стрессе −20/−30%. Скрипты `app/imp6_r3.py` (пошагово), `app/imp6_r3b.py` (что реализуемо).

Запас по правилу HL у вариантов «всё на перпах» — залог / поддерживающая маржа ≥ 7 (ликвидация только при падении портфеля на ~85–90%).

**Вывод.** Подтверждена, и поломка серьёзнее, чем ожидалось.
1. Комиссии HL: +1,3% (P9 1240 → 1256). Фандинг DOGE/PEPE 10%: P9 −4,5%; на портфелях без перп-монет отмена платы за заём BTC даёт +2–3%.
   Минимальный ордер $10: P9 −2,5%, M −1,6%, остальные ≈ 0 — терпимо, взносы просто копятся.
2. **Схема плеча из hyperliquid_exec.md (спот на v + перп на (L−1)·v, залог только USDC) небезопасна на всех пяти портфелях даже без стресса:**
   после покупок на панике (до 100% резерва) USDC не остаётся, и перп-нога живёт без залога. Отдельный залог 1:1 или 2:1 под перп-ногу не спасает
   (B и P2 при −30%). **Шорт BTC на споте-портфеле тоже небезопасен** (B/P2/P3 — 35–48 ликвидаций даже при 10%): его залог — только USDC.
3. **Исправление: держать всю позицию на перпах** (1× + плечо), USDC — общий залог. Тогда залог — весь капитал, ликвидация по HL наступает
   только при падении ~85–90%, и все варианты с плечом ≤ ×1,4 без размазывания проходят HL-правило. Цена — фандинг на весь номинал:
   при 6% годовых (средний год) P9 «в срок» 1112 против 1240 модели (−10%), при 10% — 930 (−25%). Модельное правило по-прежнему требует ×1,35
   (или 50/50 ×1,3) из-за сдвига −1.
4. Без плеча и без шорта стратегия реализуема на споте как есть (P9 +465%; DOGE/PEPE — перп 1× с полным залогом).
   Шорт BTC 20% допустим только вместе с «всё на перпах» (или на отдельном субсчёте с собственным залогом USDC ≥ номинала).

## Круг 4. OI Binance с опозданием на 1–2 дня

**Гипотеза (заранее).** Правила с OI видят данные позавчерашнего дня. Потеря сосредоточена в правиле дна «волна ликвидаций»
(oidd30 < −28: 25% резерва с плечом ×2), подтверждение паники и отложенная почти безразличны. Ценовая замена (BTC за день < −x%)
частично вернёт потерю. Критерий: сумма лог-средних (−1/0/+1) по пяти портфелям не ниже «OI вовремя» минус половина потери, 0 ликвидаций.

**Вывод.** Подтверждена по месту потери, не подтверждена по исправлению.

3. Цена BTC за день не заменяет OI: мягкий порог даёт ликвидации, жёсткий — ничего.
4. Исправление — операционное: OI того же дня брать из публичного REST Binance `futures/data/openInterestHist` (period=1d, история 30 дней — ровно столько,
   сколько нужно oidd30), архив data.binance.vision — только для сверки задним числом. Если REST недоступен, правило дна исполнять по устаревшему OI
   (это лучше, чем ценовая замена), а остальные решения дня от OI не зависят — их можно исполнять без ожидания.

## Круг 5. Округление цен Yahoo до 1e-6 (PEPE и похожие)

**Гипотеза (заранее).** Округление искажает не только PEPE: любая монета дешевле ~1e-5 на Yahoo идёт ступеньками 10–100%.
Ступеньки ломают индикаторы монеты (up90, hi90 и rel180 — 90-дн. максимум «обновляется» на каждом плато), поэтому бэктест по таким монетам
смещён на десятки процентов, но на медианах групп и портфелей (это несколько монет из многих) и на выборе правил сказывается слабо.
Критерий «искажение существенно»: изменение итога монеты > 10% или смена знака сравнения основы с предшественниками; для групп и портфелей — > 5% медианы
или новые ликвидации. Данные: дневные свечи Binance полной точности (`data-api.binance.vision`, публичный рыночный API) и kPEPE Hyperliquid —
