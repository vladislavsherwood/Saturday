# Агент улучшения №6 (imp6): реальное исполнение

Основа — `app/found/combo-best.json` + `combo-best-margin.json` (`combo2-best.json` на старте не было).
Портфельная модель — `agent4d_margin.sim4` (решение по закрытию дня t−1 исполняется по закрытию дня t; «на день позже» — по закрытию t+1).
Свои инструменты: `app/imp6_common.py` (сдвиг исполнения по семействам правил), `app/imp6_sim.py` (sim5 = sim4 + размазывание сделок,
условия Hyperliquid: комиссии по монете, перп-монеты с фандингом, минимальный ордер, ликвидация по залогу USDC + PnL перпов;
при параметрах по умолчанию совпадает с sim4 до 1e-12, `app/imp6_chk.py`).
Цифры — медиана итога к вкладам 105 стартов, лучшая безопасная схема (R16 + A4 ×1,4 + шорт BTC 20%), пять портфелей P9 / B / M / P2+BTC / P3+BTC.

## Круг 1. Какие правила чувствительны к задержке

**Гипотеза (заранее).** Потеря ~15% при исполнении на день позже сосредоточена в покупках на дне и панике (V-образные минимумы:
следующий день уже выше), продажи на вершинах к сдвигу почти безразличны. Проверка: сдвиг на +1 день решений только одного семейства,
остальные в срок; плюс сдвиг на −1 день (исполнение по закрытию дня решения — так фактически исполняет бот в 00:10 UTC, см. hyperliquid_exec.md, «открытый вопрос»).

**Вывод.** Частично подтверждена.
1. Главный источник чувствительности — **паника** (18 правил, плечо): сдвиг только её на день в любую сторону стоит P9 −6…−10%, M −22%, P3 −22…−24%.
   Дно — −3…−6%, разворот и продажа на фандинге — −2…−5%. Отложенная, возврат, тихая вершина, памп — почти безразличны (±2%).
2. **Продажа на страхе** ведёт себя наоборот: на день позже она *лучше* на четырёх портфелях из пяти (B +4%, M +7%, P2 +5%, P3 +7%), хуже только на P9 (−6%).
3. **«В срок» — острый пик:** −1 день +1126, в срок +1240, +1 день +1053, +2 дня +1039 (P9); на M 995 / 1472 / 1242 / 1232.
   **Исполнение по закрытию дня решения (как бот в 00:10 UTC) хуже, чем на день позже**, на всех портфелях, кроме P9: B −23%, M −32%, P2 −23%, P3 −37% к модели.
   Ответ на открытый вопрос hyperliquid_exec.md: исполнять сразу после закрытия нельзя — нужно исполнять **в конце дня t** (около 23:30–23:55 UTC),
   как в модели, или хотя бы во второй половине дня. Утреннее исполнение отдаёт больше, чем «опоздание на сутки».
   Пик «в срок» узкий: часть выигрыша модели — удачный выбор дня исполнения после сигнала паники (на следующий день после закрытия паники цена обычно ещё ниже).
