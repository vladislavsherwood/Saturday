# hv: combo5 на монетах с большими движениями (2026-11-20)

**Задача.** Улучшить combo5 на монетах с большими движениями (молодые, волатильные, мемы — как PUMP) и не ухудшить крупные.
**Основа** — combo5 (`found/combo5-best.json`, 58 правил) + отложенная паника `Boost(2, { k: 0, A: 0 })` + ловушка для фитилей
(−25/−40/−60% → 15/25/35% резерва, раз в 3 дня, `once`, `size: 'place'`). Отбор / экзамен / 50 случ.: 5392 / 2557 / 965.
**Инструмент** — `app/hv_lib.js` (поверх `r4_lib.js` + `h2_lib.js`; решение по вчерашнему дню, худший из сдвигов 0/1). Скрипты — `app/hv_*.js`.
Логи — `scratchpad/hv/`. Стенд `panicx_sim.js` не менял (всё — обычными правилами и полем `pol.wick.lv` функцией, которое уже есть).

**Что уже отвергнуто (не повторяю без нового поворота).** Защита разворота BTC для всех монет (h3 круг 1: rel30 > 20 → взнос +0,039 ✗; up90 > 100/200 → взнос/50% ✗;
поэтапно, у ATH, фандинг ✗); памп без BTC (h3 круг 4), стоп после пампа (h3 круг 5), продажа пампов мемов при любом BTC (seg_meme круг 5),
разовая продажа на первом дне пампа (agent3 круг 7), защита резерва после пампа (agent3 круг 1), молодые мемы без продаж на страхе (seg_meme круг 6),
P35 — паника мема только взносом, пока мем не упал (держится только на 2025–26), уровни фитилей от волатильности (wk круг 1: 100 новых лучше, 81 хуже),
светофор по бете для рыночных продаж (r4 круг 5), пол доли монеты / возврат в прорыв (r4 круг 9), продажи ×1,5 у высокобетовых (agent3 круги 2–4:
плюс, но строгая ✗ по HYPE/NPC; форма «бета > 1,2 и ниже 200д» прошла у агента 3, в combo2 не вошла).

## Сегмент «большие движения» (БД) — задан до прогонов

- **Признак дня** `hvv` = vol180 монеты (годовая волатильность дневных лог-доходностей за 180 дн, %), пока его нет (первые ~145 дней) — vol90; до ~90 дней — нет признака
  (правило не включается). **Правила БД включаются по `hvv > 115` на день решения** — по признаку, не по названию.
- 115 — верхняя треть: терцили медианы vol180 по 81 монете — 92 / 113, по дням — 84 / 116.
- **Монета в сегменте для отчёта** — медиана её `hvv` за историю ≥ 115. На 81 монете это 26 монет: отбор — PUMP; экзамен — FIL, PEPE, BONK, WIF, FLOKI, FARTCOIN;
  50 случ. — MOB, SOUL, RNDR, SRM, RGT, QRDO, HNT, POLY, MDX, ORN, HTR, ANY, NPC, TIBBIR, AERO, ORDI, ARIA, PLUME, PENGU; 100 новых — 53 монеты из 100
  (новые монеты волатильнее: их терцили 104 / 131). Из монет пользователя в сегменте: PUMP, FARTCOIN, PENGU, PEPE, USELESS, ENA; не в сегменте — HYPE (96), DOGE (95), ZEC (108).
- Крупные тоже бывают в режиме БД: доля дней с hvv > 115 — SOL 34%, ADA/LTC/BCH 20%, TRX 16%, XRP 14%, ETH/BNB 10%, BTC 2%. Поэтому проверка крупных обязательна.

## Критерий (записан до прогонов)

Кандидат принимается, если одновременно:
1. **Прибавка в сегменте БД:** доход по сегменту (Σ по отбору / экзамену / 50 случ. лог-медиан итога монет сегмента к combo5) > 0; средний лог по монетам сегмента > 0
   и на 81 монете (26 монет), и на 100 новых (53 монеты).
2. **Крупные:** доход сегмента «к» ≥ −0,005, строгая по «к» ✔, ни одна крупная монета заметно не хуже (лог итога не ниже −0,01).
3. **В целом:** строгая ✔ (вся выборка и каждый сегмент), 100 новых: средний лог > 0.
4. **Плато:** соседи по порогам и долям (±1 шаг) тоже дают плюс в сегменте; обе половины истории (доход по половинам и средний лог БД по половинам) не хуже.
5. Монеты пользователя — таблица до/после; если меняются размеры покупок — по желанию маржа ×1,45.
Сложность оправдана только прибавкой; при равенстве — оставить combo5. Отвергнутое записывается.

**Обозначения в таблицах.** «доход» — Σ лог-медиан к combo5 (всё; к / а / м); «БД доход» — то же по монетам сегмента; «БД 81» / «БД 100н» — средний лог по монетам
сегмента (лучше/хуже — монет, у которых итог изменился больше чем на 0,5 п.п.); «81» / «100н» — средний лог по всем монетам; «крупн.» — худшее изменение лога у крупной монеты.

(3) ранние продажи (16% продаж новыми копиями — перед ростом ×3, у исходных правил 11%); (4) выигрыш сосредоточен в 2023–2026; (5) маржа ×1,45 не проверена.
Скрипты — `app/hv2_*.js`, логи — `scratchpad/hv/hv2_*.log`. Основа, оценщик и **сегмент БД — те же** (признак дня `hvv` = vol180, пока его нет — vol90; монета в сегменте,
если медиана её `hvv` ≥ 115; 26 из 81, 53 из 100 новых).

**Стенд.** В `panicx_sim.js` — обратно совместимая добавка (Edit, только под полями `pol.hv_…`): `pol.hv_sell(ctx)` → новая доля продажи правила (a < 0) в день решения;
`pol.hv_after(ctx)` → доля позиции к продаже сверх правила в этот день (отложенная добавка; не в день покупки из резерва); `ctx.s` — состояние прогона. Без полей — поведение прежнее (проверено).

## Критерий hv2 (записан до прогонов)

Общий критерий hv (прибавка в сегменте на 81 и 100н; крупные ≥ −0,005, строгая «к» ✔, ни одна крупная не хуже −0,01 лога; строгая ✔; 100 новых > 0; плато; половины) — плюс по рискам:
1. **Без обрыва:** на карте параметров плавного множителя строгая ✔ на широкой полосе (не меньше 80% клеток вокруг выбранной точки), PUMP нигде в полосе не хуже combo5 больше чем на 0,02 лога.
2. **Признак вместо списка:** берётся, если крупные не хуже критерия и прибавка сегмента (БД 81, БД 100н) не меньше 90% от варианта со списком; иначе — список с объяснением.
3. **Ранние продажи:** доля провальных добавочных продаж (продано сверх combo5, затем монета ×3 и выше за 365 дн; по числу и по деньгам) ниже, чем у hv, при сохранении ≥ 80% прибавки сегмента.
4. **Эпохи:** правила, включённые только в одной эпохе, не дают минуса (БД 81, БД 100н, все 81 ≥ −0,002) ни в одной; «без одной эпохи» — прибавка сегмента > 0 всегда. При сомнении — доля ×1,5 вместо ×2.
5. **Маржа ×1,45** (по образцу `h2_margin.py`): 0 ликвидаций на 5 портфелях спот-маржи при сдвигах −1/0/+1 и на 4 перпах одного счёта при −20/−30%; запас маржи не ниже combo5 больше чем на 0,05.
